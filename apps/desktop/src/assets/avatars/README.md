# 生成头像图集（按形象配置全量适配）

与 `docs/APPEARANCE.md` 契约配套的像素风头像图集：按 `appearance` 的
{gender, skin, outfit} 三维查表，`src/lib/avatarImages.ts` 负责查表，
共享 `Avatar` 组件（`src/components/ui.tsx`）在员工有形象配置时优先
渲染本图集，查不到图时回退 `AppearanceFigure` 的 SVG 渲染，再回退
旧预设与首字色块，回退链完整。

- 维度：gender 2（f/m）× skin 5 × outfit 10 = **100 张**，512×512 PNG
- 命名：`f-s{skin}-o{outfit}.png` / `m-s{skin}-o{outfit}.png`
- 画风：与 `docs/assets/avatar-candidates/` 候选图同一像素风、大头
  头肩构图、浅灰纯色背景、无文字无边框
- 生成方式：每列（同 gender + outfit）生成一条 5 格横条（skin 1→5
  由浅到深），按背景列密度定位人像后逐格裁切、底色补方
- 发型：不在查表维度内，每列统一采用一个契约内发型，编号见下表
  「hair」列。因此在形象选择器里改发型不会改变生成图（图集按三维
  查表），这是本图集的已知口径；面板头像与工作室精灵仍是同一人
  （性别/肤色/服装三项一致，精灵发型按配置逐帧渲染）

## 生成与重生成记录

- 首轮 20 条横条中，男性 6 条（m-o1 至 m-o6）不合格并整条重生成：
  参考图（陈工候选带耳机）的耳机被模型带进了无配饰的列
  （o1/o2/o6 不应有耳机、o4 应只有眼镜），m-o3 首轮画风粗糙、
  与候选不是同一人。重生成时对无耳机列改用无耳机参考图并明示
  「no headphones, bare ears」，o3 仍用陈工候选并强调细腻画风；
  6 条重生成后全部合格。其余 14 条首轮即合格。
- 切割踩过的坑（已修在切割脚本里）：紧密排布的横条里肩部会连成
  整带，按全高列密度找簇会把 5 人并成 1 簇，改用头部区（上 55%）
  列密度；相邻人像间隙可窄到 3px，簇合并阈值须小于间隙；人像
  高度大于间距时居中方形裁切必然吞掉邻居，最终方案是按簇间中点
  切分本格区域、底色补方，保证不串格。

## 与 AI 工作室精灵的配色对齐核对

结论：**同源、无分叉，不需要改精灵代码。**

- 精灵渲染 `features/pixel-studio/game/textures.ts` 的 `charOpts`
  全部经 `skinBase / hairDef / outfitDef` 从 `src/lib/appearance.ts`
  取值：肤色主色、发色、上衣主色、搭配色、领型、配饰均与契约
  同一份定义；全目录 grep 无任何硬编码的肤色/发色/衣色副本。
- 派生色口径按契约执行：精灵肤色阴影为基准色 ×0.78 / ×0.62、
  高光 ×1.04+4，平面头像颈部阴影为基准色叠 8% 黑——基准同源，
  明暗派生是契约允许的渲染器差异（契约原文：像素精灵按同一
  口径取暗一档即可）。裤装为装扮 10 取 #242424、其余取上衣主色
  ×0.72，亦为派生而非另一套色值。
- 本图集的生成提示词逐列写明契约色值（肤色五档与上衣主色均带
  hex），生成结果逐格核对主色与契约一致；因此面板头像（本图
  集）与场景精灵（程序化渲染）按同一编号呈现同一人：同性别、
  同肤色档、同服装款与配饰。
